## 现状

1. **棋盘不是正方形**：`.cell` 是 `width: var(--cell); height: calc(var(--cell) * 1.12)`，`updateCellSize()` 里也按 `/ 1.12` 折算行高。所以整块地图永远是竖向拉长的长条，横向留出大量空白。
2. **地图尺寸没有「总是最大」的保证**：`updateCellSize()` 取 `boardWrap.clientWidth/clientHeight` 反推格子，但容器本身是 `flex-grow:1` 的弹性盒子，桌面端 `#game` 又是 `justify-content: center`，地图被侧栏挤在中间，左右都不贴边。
3. **地图本身不严格正方**：`initLevel` 里 `ROWS = COLS = baseSize + …`，但每 3 关会 `ROWS += 1; COLS += 2`（上限 25）→ 第 3/6/9… 关是 12×14 这种长方形。
4. **六维图常驻占位**：`#hero > #radarWrap > canvas#radarCanvas`，桌面端 `#sidebar` 宽 `clamp(300px, 33vw, 620px)`，雷达图长期吃掉侧栏上半部分；手机竖版也一直占着一块。
5. **手机端没有任何虚拟按键**：操作全靠在棋盘上点 / 长按、在角色卡「仪表格」上点（步数=等待、攻击=攻击节点、伤害=显示范围），外加键盘 WASD / E / R / Q / 空格 / X。手机上等于只能靠手指点小格子，`长按=等待` 尤其难按。
6. **开始行动没有任何反馈过程**：点 `.start-btn` → `confirmAction()` 立刻 `phase = PHASE.RESOLVING`、`render()`，然后 `setTimeout(() => resolveStep(1, 0), 300)`。攻击掷骰发生在 `resolveStep` 内部（`attackRoll()` 现掷），玩家只能事后在日志里看到 `d20=…`，看不到「我在掷骰」这件事。

## 期望

### A. 棋盘：正方形、始终取最大

- 棋盘容器 `#boardWrap` 固定为**正方形**：边长 = 可用区域的短边（`min(可用宽, 可用高)`），不随地图行列数变化。
- `.cell` 改为 **1:1**（去掉 1.12 系数），`updateCellSize()` 相应的 `/ 1.12` 一并去掉；`--cell` 的上下夹取（16~80）保留。
- 格子边长 = `floor((正方形边长 - 内边距 - 格间隙) / max(ROWS, COLS))`，地图在正方形内**居中**；`ROWS ≠ COLS` 的关卡（第 3/6/9… 关）短边方向留白，不允许溢出、不允许出现滚动条。
- 窗口尺寸变化 / 切换布局 / 进入新关卡后，棋盘始终填满可用空间的短边（±2px 内），不存在「地图变小了一圈」的情况。

### B. PC 端布局

- 地图**贴左**：`#game` 的 `justify-content` 从 `center` 改为 `flex-start`（保留原有内边距），地图左侧与视口左边齐平不再居中。
- 六维图从侧栏**移出**，改为**弹窗**：默认不占任何布局空间；点击入口按钮才弹出，交互范式对齐现有「设置」浮窗（可拖动 / 可关闭 / 有标题栏）。
- 入口：侧栏顶部一个方形按钮（如「六维 ⌗」，配 `aria-label`），点击弹出；再次点击或点 ✕ 关闭。
- **右键在棋盘路径格上设立 / 取消技能节点**：`contextmenu` 拦截且 `preventDefault()`；只在「该格在当前规划路径上」时生效，效果等价于现在「双击路径节点」（`setSkillNode`）。右键非路径格 → 不弹浏览器菜单、不产生任何节点、给一条日志提示。

### C. 手机端布局（≤760px，layout-v）

- 地图**贴上面**：地图贴顶，正方形占满宽度（高度同宽），不留上边距。
- 六维图同样改成**弹窗**，且是**从右侧滑出的抽屉**，可以**遮盖地图**（overlay + 半透明遮罩），点遮罩或 ✕ 关闭。
- 关卡结束时**主动弹出**属性面板让玩家加点：奖励弹窗关掉后若 `playerStats.abilityPoints > 0`，自动滑出抽屉；点数加完自动收起，`下一关` 按钮才可点。

### D. 手机端虚拟按键

- 左下：**十字方向键**（与键盘方向键同布局：上 / 下 / 左 / 右四键），四键均为**圆形**，按下即等价于对应方向键的移动（复用现有 `movePlayer` 逻辑，不新写寻路）。
- 右下：**等待 / 攻击 / 技能**三键，同为**圆形**，位置与现有按钮语义一致；键面数值：
  - **等待** = 剩余可等待步数 `player.move - countWaitSteps(playerPath)`
  - **攻击** = 该角色对应伤害（近战角色取 `meleeDmg`、远程取 `rangedDmg`）；若本回合已有多个攻击节点，右上角小角标 `×N`
  - **技能** = 当前技力 `spNow`
- **技力环**：技能键外圈画一圈环，环按 `spMax` **等分成 spMax 个扇段**；`spNow` 个段点亮，其余暗色。即满技力 = 完整闭合环，半技力 = 正好半圈，1/4 = 一个象限（spMax 不整除 360 时按角度均分，最后一段余数补齐）。环上不显示数字以外的装饰。
- 三键行为与现有「仪表格 / 键盘 E、R、Q」完全一致，不得出现第二套语义（同一函数出口）。
- 手机端隐藏「开始行动」以外的键盘提示文案；按钮区需避开底部安全区（`env(safe-area-inset-bottom)`）。

### E. 设计语言：方形 = 信息，圆形 = 交互

- **可点击的一律圆形**：方向键、等待 / 攻击 / 技能、开始行动（可保留胶囊形，属按钮）、弹窗关闭键。
- **信息一律方形/矩形**：角色卡、仪表格（步数/攻击/技能/伤害）、日志、属性条、词缀标签、关卡信息。
- 执行落地要求：把现在「卡面仪表格可点击（步数=等待 / 攻击=攻击节点 / 伤害=显示范围）」这件事**取消掉**（PC 与手机一致），仪表格降级为纯展示；交互只保留 圆形按钮 + 键盘。→ 与「方形是信息」冲突的部分必须收敛。
- 圆钮统一：直径 ≥44px（触屏最小点击区）、`border-radius:50%`、按下态有内缩/亮度反馈；禁用态降透明度并 `pointer-events:none`。

### F. 「开始行动」→ D20 六边形掷骰

- 点击「⚔️ 开始行动」后：
  1. 按钮**变灰**（`disabled` + 降饱和），文字保留，期间不可重复触发（键盘空格同样锁死）。
  2. 按钮中间出现一个**正六边形轮廓**（代表 D20），**旋转**（≥600ms，`ease-out`），期间内部数字快速跳动（可选）。
  3. 旋转**停下**，六边形中间显示**本次掷骰结果**（d20 点数；自然 20 / 自然 1 用金 / 红色区分）。
  4. 结果展示约 300ms 后，才开始真正的移动与结算（即替换 `confirmAction` 末尾的 `setTimeout(() => resolveStep(1,0), 300)`）。
- **显示值必须是实际结算用的那一颗 d20**，不允许「为动画另掷一次」。实现约束见「涉及区域 · 硬约束」。
- 本回合没有攻击节点时：按钮同样灰化，六边形只转不显示数字（中间显示 `—`），或直接跳过动画——二选一，实现时取「转一次 + `—`」，避免玩家以为点击没生效。
- 一回合有多个攻击节点时，六边形只展示**第一个**攻击节点的 d20，其余照旧走日志。
- PVP 模式（`mode === 'pvp'`）**不播这段动画**，`pvpSubmitPlan()` 保持原样直发，避免网络请求被动画阻塞。

### 硬约束 / 已知坑（务必按此实现）

1. **D20 预掷必须复用，不能重掷**：在 `prepareWheelchairCharge()`（会改写路径、可能吞掉攻击节点）**之后**、`resolveStep(1,0)` **之前**，按修正后的 `attackIndices` 顺序调用一次 `attackRoll()` 并缓存（数组 + 消费游标）。结算侧 5 处 `attackRoll` 入口改成 `takePendingRoll() || attackRoll(...)`——**必须保留 fallback**，否则 PVP / 异常路径会因缓存为空而炸。
2. **允许随机序列相对旧版前移**：预掷会让本回合 d20 提前消耗全局 rng，逐局结果与 20261028d 不再一致。这是可接受的（无存档回放），但**必须做平衡回归**（见验收 12），并确认 `enemyGrowthRng` / `affixRng` 这类独立种子链未被污染（它们不用全局 `rng()`，理论上安全）。
3. **`confirmAction` 会变成 async**：`confirm.onclick = confirmAction` 无影响，但空格键路径（`handleKeyDown`）与棋盘点击都必须在动画期间加 `resolvingLock`，否则连点两下会双结算。动画期间 `phase` 建议保持 `PLANNING` 到动画结束再置 `RESOLVING`，或置 `RESOLVING` 前先 `inputLocked = true`。
4. **`drawRadar()` 在隐藏容器里 `clientWidth === 0`**：弹窗用 `display:none` 时必须「先显示 → 再 `requestAnimationFrame(drawRadar)`」，否则画布被压成 0×0；`radarLabelHits` 命中框在打开 / 缩放 / 滚动后要重算（现在是 `getBoundingClientRect()` 相对坐标，弹窗内会偏）。
5. **正方形 vs 竖版拖动条**：`mapVRatio` / `applyMapVHeight()` 会写死 `boardWrap.style.height`，和「正方形总是最大」互斥。正方形落地后，竖版**移除拖动条**（`#dragHandle` 在 `layout-v` 下 `display:none`），并清掉 `localStorage['ark_map_v_ratio']` 的旧值影响。
6. **`ROWS ≠ COLS` 的关卡**：不能为了「正方形」去改 `initLevel` 的行列数（那是平衡与地图生成的一部分，改了两百多关的地图都变）。只让容器正方 + 格子正方 + 居中。
7. **触屏事件**：方向键用 `pointerdown` 触发（不要用 `click`，会有 300ms 延迟感），并 `touch-action: none` 防页面滚动/双击缩放。
8. **右键技能节点**：`contextmenu` 只在棋盘格上拦截；`skillIndices` / `attackIndices` 互斥规则、动作上限校验必须走现有 `setSkillNode()`，不要另写一份校验。

## 备注

### 3 条默认假设（实施时按此走，维护者可否掉）

1. **PC 端也显示圆形按钮组**：既然「方形=信息、圆形=交互」，PC 不接受「仪表格可点」这套旧交互。PC 上圆钮常驻可点（鼠标），键盘快捷键保留不变。若维护者希望 PC 端只留键盘，则删掉 `mobile-pad.js` 的桌面分支即可。
2. **关卡通过自动弹属性面板，PC 与手机都做**（不只是手机）：手机是右抽屉，PC 是浮窗。原因：雷达图改成弹窗后，PC 的 LEVELCLEAR 提示「请点击左侧六维图」已经不成立。
3. **属性面板自动弹出的时机在「奖励选完之后」**：`openLevelUp()` 的奖励弹窗先弹，选完若 `abilityPoints > 0` 再弹属性面板，两窗不叠加。若维护者希望先加属性再选奖励，改 `openLevelUp` 的调用顺序即可。

### 与其他 issue 的关系

- 与 `ISSUE-20261028-07-icon-system`（像素图标）**有交汇**：圆钮/仪表格里若也放角色头像，等 07 素材到位后统一替换，本 issue 先不引入 `<img>`。

### 拆分建议（体量太大，建议分两次发版）

本轮建议**只做 A + B + C + D + E**（布局与交互重排），做完发一版；**F（d20 动画）单独一版**。原因：F 要动 `confirmAction` 与 5 处 `attackRoll`，属于结算热区，和布局回归混在一起时，出问题无法快速二分定位。
