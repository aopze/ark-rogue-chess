## 现状

1. **棋盘不是正方形**：`.cell` 是 `width: var(--cell); height: calc(var(--cell) * 1.12)`，`updateCellSize()` 里也按 `/ 1.12` 折算行高。所以整块地图永远是竖向拉长的长条，横向留出大量空白。
2. **地图尺寸没有「总是最大」的保证**：`updateCellSize()` 取 `boardWrap.clientWidth/clientHeight` 反推格子，但容器本身是 `flex-grow:1` 的弹性盒子，桌面端 `#game` 又是 `justify-content: center`，地图被侧栏挤在中间，左右都不贴边。
3. **地图本身不严格正方**：`initLevel` 里 `ROWS = COLS = baseSize + …`，但每 3 关会 `ROWS += 1; COLS += 2`（上限 25）→ 第 3/6/9… 关是 12×14 这种长方形。
4. **六维图常驻占位**：`#hero > #radarWrap > canvas#radarCanvas`，桌面端 `#sidebar` 宽 `clamp(300px, 33vw, 620px)`，雷达图长期吃掉侧栏上半部分；手机竖版也一直占着一块。
5. **手机端没有任何虚拟按键**：操作全靠在棋盘上点 / 长按、在角色卡「仪表格」上点（步数=等待、攻击=攻击节点、伤害=显示范围），外加键盘 WASD / E / R / Q / 空格 / X。手机上等于只能靠手指点小格子，`长按=等待` 尤其难按。
6. **开始行动没有任何反馈过程**：点 `.start-btn` → `confirmAction()` 立刻 `phase = PHASE.RESOLVING`、`render()`，然后 `setTimeout(() => resolveStep(1, 0), 300)`。攻击掷骰发生在 `resolveStep` 内部（`attackRoll()` 现掷），玩家只能事后在日志里看到 `d20=…`，看不到「我在掷骰」这件事。
7. **设置面板是一个可拖动悬浮窗**：`#logPanel` + `position:absolute` + `LOG_POS_KEY` 记住位置 + `bindLogDrag` 按住标题栏拖。这与「不要凭空悬浮」直接冲突，要整体废弃。

## 期望

### A. 棋盘：正方形、始终取最大

- 棋盘容器 `#boardWrap` 固定为**正方形**：边长 = 可用区域的短边（`min(可用宽, 可用高)`），不随地图行列数变化。
- `.cell` 改为 **1:1**（去掉 1.12 系数），`updateCellSize()` 相应的 `/ 1.12` 一并去掉；`--cell` 的上下夹取（16~80）保留。
- 格子边长 = `floor((正方形边长 - 内边距 - 格间隙) / max(ROWS, COLS))`，地图在正方形内**居中**；`ROWS ≠ COLS` 的关卡（第 3/6/9… 关）短边方向留白，不允许溢出、不允许出现滚动条。
- 窗口尺寸变化 / 切换布局 / 进入新关卡后，棋盘始终填满可用空间的短边（±2px 内），不存在「地图变小了一圈」的情况。

### B. PC 端布局

- 地图**贴左**：`#game` 的 `justify-content` 从 `center` 改为 `flex-start`（保留原有内边距），地图左侧与视口左边齐平不再居中。
- 六维图从侧栏**移出**，改为**从右边缘滑出的侧边栏抽屉**：默认不占任何布局空间；点击入口按钮才滑出，`transform: translateX(100%) → 0`，**不允许做成可拖动的悬浮窗**（用户明确要求「不要凭空悬浮」，现有的 `#logPanel` 悬浮范式整体废弃）。
- 入口：侧栏顶部一个方形按钮（如「六维 ⌗」，配 `aria-label`），点击滑出；再次点击、点 ✕ 或点遮罩关闭。
- **右键在棋盘路径格上设立 / 取消技能节点**：`contextmenu` 拦截且 `preventDefault()`；只在「该格在当前规划路径上」时生效，效果等价于现在「双击路径节点」（`setSkillNode`）。右键非路径格 → 不弹浏览器菜单、不产生任何节点、给一条日志提示。
- **PC 端不出现任何虚拟按钮**（用户明确要求）：没有方向键、没有等待 / 攻击 / 技能圆钮、没有技力环。PC 的交互只有三种：点击棋盘规划路径、右键设 / 取消技能节点、键盘（WASD 移动 · E 攻击 · R 技能 · Q 等待 · V 攻击范围 · 空格确认 · X 重置 · F12 调试）。

### C. 手机端布局（≤760px，layout-v）

- 地图**贴上面**：地图贴顶，正方形占满宽度（高度同宽），不留上边距。
- 六维图同样是**从右侧滑出的抽屉**（与 PC 共用同一套组件、同一个边），可以**遮盖地图**（overlay + 半透明遮罩），点遮罩或 ✕ 关闭。
- 关卡结束时**主动弹出**属性面板让玩家加点：奖励抽屉关掉后若 `playerStats.abilityPoints > 0`，自动滑出**同一个**属性抽屉；点数加完自动收起，`下一关` 按钮才可点。

### D. 手机端虚拟按键（仅手机渲染，PC 一律不建 DOM）

- **挂载判据**：`(pointer: coarse)` 成立且 `(any-pointer: fine)` 不成立 → 才创建按钮 DOM。桌面 / 带触摸屏的笔记本（有鼠标，`any-pointer: fine` 成立）**不渲染**；浏览器不支持该媒体查询时退回 `innerWidth <= 760`。判据只决定「建不建」，与布局模式 `layout-h/v` 解耦。
- 左下：**十字方向键**（与键盘方向键同布局：上 / 下 / 左 / 右四键），四键均为**圆形**，按下即等价于对应方向键的移动（复用现有 `movePlayer` 逻辑，不新写寻路）。
- 右下：**等待 / 攻击 / 技能**三键，同为**圆形**，位置与现有按钮语义一致；键面数值：
  - **等待** = 剩余可等待步数 `player.move - countWaitSteps(playerPath)`
  - **攻击** = 该角色对应伤害（近战角色取 `meleeDmg`、远程取 `rangedDmg`）；若本回合已有多个攻击节点，右上角小角标 `×N`
  - **技能** = 当前技力 `spNow`
- **技力环**：技能键外圈画一圈环，环按 `spMax` **等分成 spMax 个扇段**；`spNow` 个段点亮，其余暗色。即满技力 = 完整闭合环，半技力 = 正好半圈，1/4 = 一个象限（spMax 不整除 360 时按角度均分，最后一段余数补齐）。环上不显示数字以外的装饰。
- 三键行为与现有「仪表格 / 键盘 E、R、Q」完全一致，不得出现第二套语义（同一函数出口）。
- 手机端不显示键盘快捷键提示文案（WASD / E / R / Q / 空格 / X 那一行），换成一行触摸说明；按钮区需避开底部安全区（`env(safe-area-inset-bottom)`）。
- 手机端「开始行动」**保持胶囊按钮**（与 PC 同一组件、同一宽度策略），横向铺在方向键与三键之间的空隙上方，**不改成圆钮** —— 它是特殊按钮，中间要显示掷骰结果（见 F）。

### E. 设计语言：方形 = 信息，圆形 = 交互，浮层 = 侧边栏

- **圆形 = 交互**：仅手机端的虚拟按键（方向键、等待 / 攻击 / 技能、技力环、抽屉关闭键）。PC 端不引入任何圆形按钮，这条原则在 PC 上体现为「不提供可点的方表格」，而不是「换成圆形」。
- **胶囊 = 特殊动作**：只有「开始行动」是胶囊（两端一致）。它是唯一带过程反馈（D20 旋转 → 结果）的按钮，形状上要和普通信息块、圆形按键都区分开。
- **方形 / 矩形 = 信息**：角色卡、仪表格（步数 / 攻击 / 技能 / 伤害）、日志、属性条、词缀标签、关卡信息、抽屉本体。
- **浮层 = 从屏幕边缘滑入的侧边栏**：不存在「凭空悬浮的窗口」。设置、六维图、属性说明、升级奖励、属性加点全部走同一套抽屉组件（见 G）。
- **执行落地要求**：把现在「卡面仪表格可点击（步数=等待 / 攻击=攻击节点 / 伤害=显示攻击范围）」这件事**取消掉**（PC 与手机一致），仪表格降级为纯展示。手机端的等待 / 攻击 / 技能全部由圆形按钮承担；PC 端由键盘承担。
- **被取消的「伤害格=显示攻击范围」必须补回入口**（否则是功能回退）：PC 增加键盘 `V` 切换攻击范围显示；手机**长按攻击圆钮**（≥400ms）切换，短按仍是设攻击节点。两处最终都走现有 `showRangeOverlay` 开关，不要复制逻辑。
- 圆钮统一（仅手机）：直径 ≥44px（触屏最小点击区）、`border-radius:50%`、按下态有内缩 / 亮度反馈；禁用态降透明度并 `pointer-events:none`。

### F. 「开始行动」→ D20 六边形掷骰

- 按钮形态：PC 与手机**都是胶囊** `.start-btn`（同一组件、同一文案「⚔️ 开始行动」）。手机端把它铺在方向键与三键之间的空隙上方，宽度占满留给它的列；高度 ≥44px。**不改成圆形**，因为它是唯一要塞掷骰过程与结果的按钮。
- 六边形在胶囊内**居中**，边长 ≈ 胶囊高度的 55%，不挤压文字（文字在左、六边形在右，或文字淡出后六边形居中，二选一，优先前者）。
- 点击「⚔️ 开始行动」后：
  1. 按钮**变灰**（`disabled` + 降饱和），文字保留，期间不可重复触发（键盘空格同样锁死）。
  2. 按钮中间出现一个**正六边形轮廓**（代表 D20），**旋转**（≥600ms，`ease-out`），期间内部数字快速跳动（可选）。
  3. 旋转**停下**，六边形中间显示**本次掷骰结果**（d20 点数；自然 20 / 自然 1 用金 / 红色区分）。
  4. 结果展示约 300ms 后，才开始真正的移动与结算（即替换 `confirmAction` 末尾的 `setTimeout(() => resolveStep(1,0), 300)`）。
- **显示值必须是实际结算用的那一颗 d20**，不允许「为动画另掷一次」。实现约束见「涉及区域 · 硬约束」。
- 本回合没有攻击节点时：按钮同样灰化，六边形只转不显示数字（中间显示 `—`），或直接跳过动画——二选一，实现时取「转一次 + `—`」，避免玩家以为点击没生效。
- 一回合有多个攻击节点时，六边形只展示**第一个**攻击节点的 d20，其余照旧走日志。
- PVP 模式（`mode === 'pvp'`）**不播这段动画**，`pvpSubmitPlan()` 保持原样直发，避免网络请求被动画阻塞。

### G. 所有浮层统一成「侧边栏抽屉」+ 属性说明

**G1 抽屉规格（一套组件，四处复用）**

| 承载内容 | 入口 | 收起方式 |
|---|---|---|
| 设置（原 `#logPanel` 悬浮窗：主页/联机/重开/旋转 + 战斗日志） | 左上角 ⚙（位置不变） | ✕ / 点遮罩 / 再点 ⚙ |
| 六维图 + 属性加点（**同一个抽屉**：平时看数值，通关时顶部多一行「剩余点数」并可加点） | 侧栏顶部方形按钮（手机端为底部「六维」圆形入口） | ✕ / 点遮罩 |
| 属性说明（点属性名后） | 六维抽屉内点属性名 | 「← 返回」/ 点遮罩 |
| 升级奖励选择（`openLevelUp`） | 通关自动 | 选完自动收 |

- **统一从右侧滑入**（与手机端六维抽屉同一个边），`transform: translateX(100%) → 0`，220ms `ease-out`；宽度 `min(360px, 86vw)`；顶部标题栏（标题 + ✕），标题栏是矩形信息块（与「方形=信息」一致）。
- 遮罩 `rgba(0,0,0,.45)`，点遮罩关闭；遮罩只覆盖游戏区，不覆盖抽屉本体。
- **同一时刻只允许一个抽屉打开**：打开新的自动收起旧的（`drawerOpen(id)` 里有互斥逻辑）。z-index 收成单一变量 `--z-drawer`，禁止各处硬编码。
- **现有的悬浮窗范式整体废弃**：删掉 `LOG_POS_KEY` / `clampLogPanelPos()` / `bindLogDrag()` 与 `#logPanel` 的绝对定位拖动；`localStorage['ark_log_pos']` 读到也直接忽略（不要迁移，布局已完全不同）。
- 抽屉打开时入口按钮保持可见并进入高亮态（`aria-expanded="true"`）；`Esc` 关闭当前抽屉（PC）。

**G2 属性说明（点击六维图上的属性名）**

- 点击属性名 → 在**同一个抽屉内**从右侧再滑入一层「属性说明卡」，**不新开浮层**；「← 返回」回到六维图。层级栈由抽屉组件自己维护，最多 2 层。
- 说明卡内容：属性全称、当前值、修正值 `abilityLabel()`、一句话作用、以及具体影响的数值项（下列数值**必须与代码现状一致**，不许凭印象写）。

| 属性 | 说明卡正文（照抄即可） |
|---|---|
| 力量 str | **近战伤害与近战命中**。近战伤害 = 1 + 力量修正；风笛 / 泥岩 用这一条。 |
| 敏捷 dex | **移动力与防御等级**。移动力 = ⌊敏捷 / 2⌋；AC = 5 + ⌊(敏捷 + 体质) / 4⌋。 |
| 体质 con | **生命上限**。maxHp = 体质 + 4 + 等级加成；同时参与 AC 公式。 |
| 智力 int | **远程伤害与远程命中**。远程伤害 = 1 + 智力修正；阿米娅 / 华法琳 用这一条。 |
| 感知 wis | **战场预判与技力上限**。敌人意图可见步数 = 1 + max(0, 感知修正)；部分角色的技力上限 = 感知值。 |
| 魅力 cha | **当前版本无任何数值作用**（只显示、只参与面板展示）。→ 见「备注 · 新发现的设计空洞」。 |
| 熟练加值（非属性） | 命中检定 = d20 + 属性修正 + 熟练加值；熟练 = 4 + (角色等级 − 1)。 |

- **加点入口不能丢**：现在「点属性名 = 加点」是唯一入口。改造后：说明卡底部放一个方形的「+1」按钮（`abilityPoints > 0` 且该属性 < 20 时可用），点击加点并原地刷新说明卡数值；六维图上仍保留属性名外圈的金色方框作为「可加点」提示。**不允许把加点入口挪进另一个抽屉**（会变成两次点击才能加一点，手机端尤其难受）。

### 硬约束 / 已知坑（务必按此实现）

1. **D20 预掷必须复用，不能重掷**：在 `prepareWheelchairCharge()`（会改写路径、可能吞掉攻击节点）**之后**、`resolveStep(1,0)` **之前**，按修正后的 `attackIndices` 顺序调用一次 `attackRoll()` 并缓存（数组 + 消费游标）。结算侧 5 处 `attackRoll` 入口改成 `takePendingRoll() || attackRoll(...)`——**必须保留 fallback**，否则 PVP / 异常路径会因缓存为空而炸。
2. **允许随机序列相对旧版前移**：预掷会让本回合 d20 提前消耗全局 rng，逐局结果与 20261028d 不再一致。这是可接受的（无存档回放），但**必须做平衡回归**（见验收 12），并确认 `enemyGrowthRng` / `affixRng` 这类独立种子链未被污染（它们不用全局 `rng()`，理论上安全）。
3. **`confirmAction` 会变成 async**：`confirm.onclick = confirmAction` 无影响，但空格键路径（`handleKeyDown`）与棋盘点击都必须在动画期间加 `resolvingLock`，否则连点两下会双结算。动画期间 `phase` 建议保持 `PLANNING` 到动画结束再置 `RESOLVING`，或置 `RESOLVING` 前先 `inputLocked = true`。
4. **`drawRadar()` 在隐藏容器里 `clientWidth === 0`**：抽屉用 `display:none` 时必须「先显示 → 再 `requestAnimationFrame(drawRadar)`」，否则画布被压成 0×0；`radarLabelHits` 命中框在打开 / 缩放 / 滚动后要重算（现在是 `getBoundingClientRect()` 相对坐标，抽屉内会偏）。
5. **正方形 vs 竖版拖动条**：`mapVRatio` / `applyMapVHeight()` 会写死 `boardWrap.style.height`，和「正方形总是最大」互斥。正方形落地后，竖版**移除拖动条**（`#dragHandle` 在 `layout-v` 下 `display:none`），并清掉 `localStorage['ark_map_v_ratio']` 的旧值影响。
6. **`ROWS ≠ COLS` 的关卡**：不能为了「正方形」去改 `initLevel` 的行列数（那是平衡与地图生成的一部分，改了两百多关的地图都变）。只让容器正方 + 格子正方 + 居中。
7. **触屏事件**：方向键用 `pointerdown` 触发（不要用 `click`，会有 300ms 延迟感），并 `touch-action: none` 防页面滚动/双击缩放。
8. **右键技能节点**：`contextmenu` 只在棋盘格上拦截；`skillIndices` / `attackIndices` 互斥规则、动作上限校验必须走现有 `setSkillNode()`，不要另写一份校验。
9. **抽屉内容必须能在 `render()` 之后存活**：`render()` 现在会重刷侧栏与卡面，若抽屉把 DOM 直接挂在 `#sidebar` 里，每次加点触发的 `render()` 都会把说明卡冲掉（玩家点一次 +1 就退出说明卡）。抽屉节点必须挂在 `#sidebar` **之外**的独立容器（`body` 直属），内容的刷新走「只更新数值文本」而不是重建整棵树。
10. **`Esc` 与 `X` 的冲突**：`Esc` 关闭抽屉后要 `stopPropagation`，避免顺带触发 `handleKeyDown` 里的其它键位逻辑；`X` 仍是重置路径，不要被抽屉拦截。
