- **尺寸**：原生 64×64。游戏显示 27.5px，`image-rendering: pixelated` 下缩到 ~28px 清晰；也具备做选角大图（3×=72px）的余量（矢量无关，放大不糊）。

- **交付物**：`assets/amiya.png`（64×64 硬边版，alpha 已阈值化 a≥128→不透明）。实施时按 07 号 §实施规范 内嵌为 base64，**增量约 4KB**。
- ⚠️ **提取注意**：Krita `mergedimage.png` 会被陈旧化 / 图层独立 PNG 为内部格式（非标准 PNG 头），提取须解包 `.kra`（zip）后正确解码 `mergedimage.png` 并做滤波重建，不能当普通文件直接读。

### 核心结论：像素画可以内嵌，单文件约束完全保住

实测（索引色 PNG + 透明背景，模拟真实像素画的色块分布）：

| 画布 | 调色板 | PNG | base64 内嵌 |
|---|---|---|---|
| 16×16 | 16 色 | **201 B** | 268 B |
| **24×24** | **32 色** | **279 B** | **372 B** |
| 32×32 | 32 色 | 301 B | 401 B |
| 48×48 | 32 色 | 315 B | 420 B |

**总量估算（24×24 / 32 色）**

| 内容 | 内嵌 base64 增量 |
|---|---|
| 4 张（只有正常态） | **≈ 1.5 KB** |
| 12 张（4 角色 × 3 状态：正常 / 受伤 / 眩晕） | ≈ 4.4 KB |
| 16 张（4 角色 × 4 状态） | ≈ 5.8 KB |

> 真实手绘细节更多，按每张 300–800 B 估，**4 角色全套仍远小于 10 KB**（基数 261,228B，增重 < 4%）。

**对比此前放弃的外链方案**：外链要 +3KB 且失去离线能力；**内嵌像素画 +1.5~6KB 却完整保留单文件分发**。这是本方案最大的优势。

### 绘制规范（素材侧）

| 项 | 建议值 | 说明 |
|---|---|---|
| **画布** | **24×24**（主推） | 与当前 emoji 27.5px 显示尺寸接近，**不会破坏现有布局**；细节足够表现发型/武器。备选 32×32（更精细，但显示 32px 占格子 64%） |
| 显示尺寸 | **24 px（1×）** | ⚠️ **必须整数倍**。24×24 在 DPR2 屏 = 48 物理 px，正好 2× 最近邻，完美清晰 |
| **背景** | **透明**（alpha） | 棋盘底色 `#1a1a2e` 系，不要用白色底 |
| 调色板 | **16–32 色**，4 角色共用一套底色板 | 风格统一的关键。推荐现成调色板：**Endesga 32** / **DawnBringer 32（DB32）** / Lospec 筛选 |
| 视角 | **正面头像 / 半身像** | 棋盘是图标式俯视布局，正面像最易辨识，且不需处理朝向（朝向已有独立 `facing-ind` 指示器） |
| 导出 | **PNG，索引色，关闭抗锯齿** | 抗锯齿会引入中间色，破坏像素感并增大体积 |

### 实施规范（代码侧）

**1. 必须加 `image-rendering: pixelated`**（否则浏览器双线性插值会把像素画糊成一团）

```css
.unit .icon img, .unit-abs .icon img {
  image-rendering: pixelated;              /* Chrome / Safari / Firefox */
  image-rendering: crisp-edges;            /* 兜底 */
  -ms-interpolation-mode: nearest-neighbor;
  width: 24px; height: 24px;               /* ★ 必须写死整数 px，不能写 100% 或不设 */
}
```

> ⚠️ **最大坑**：`.icon` 当前样式是 `font-size: calc(var(--cell)*0.55)`（给 emoji 用的），**`<img>` 完全不受 font-size 影响**。若不显式给 `width/height`，img 会按原始尺寸（24px）显示——看似没问题，但一旦 `--cell` 被用户在设置里调小，emoji 会跟着缩而 **img 不会**，两套图标立刻错位。建议显式设 `width/height: 24px`（或读取 `--cell` 计算后取整）。

**2. 状态着色：优先手绘变体，不用 CSS filter**

像素画靠**有限色阶建立明暗关系**，`hue-rotate` / `sepia` 会直接毁掉调色板（比对立绘更致命）。

- ✅ **推荐**：手绘状态变体，横向拼成雪碧图，用 `background-position` 切换（每张仅 +300B）
  - 状态：**正常 / 受伤（泛红）/ 眩晕（灰调）**；角色不需要「敌方」变体（敌人是 emoji）
- ⚠️ **降级**（若暂不画变体）：只保留两个对像素画安全的 filter —— 眩晕 `filter: grayscale(1)`（安全）、受击闪烁 `filter: brightness(1.4)`（安全）
- ❌ **禁止**：`sepia` / `hue-rotate` / `saturate`（对像素画有破坏性）

**3. 内嵌方式**

```html
<!-- 或作为 CSS background-image 的 data URI -->
<img class="px-icon" src="data:image/png;base64,iVBORw0KGgo…" alt="阿米娅">
```

建议集中在**一个常量表**里（如 `const CHAR_SPRITES = { amiya: 'data:image/png;base64,…', … }`），**不要散落在渲染逻辑里**——Amechihaya 正在拆 `src/**`，结构化常量表能整块搬走。

**4. 渲染分支**

角色走 `<img>`，敌人继续 emoji 文本 —— 1734 行 `rec.icon.textContent = u.icon` 需改成分支写法（图标是内部常量，XSS 面极低）。
