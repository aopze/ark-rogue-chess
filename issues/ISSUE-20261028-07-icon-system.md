### 4. emoji 已在本项目闯过一次祸（重要背景）

- **历史 bug（v5 修复）**：`body` 字体栈里 emoji 字体（Noto Color Emoji）位置靠前，而它自带数字字形 → 微信 X5 内核优先命中，**HP 数字被渲染成全角**（`HP8 / 8` 显示成 `HP８ / ８`）。
- 修复方式：文本字体在前、emoji 字体垫后。**当前字体栈（第 10 行）**：
  ```css
  body { font-family: system-ui, -apple-system, "HarmonyOS Sans SC", "PingFang SC", "Microsoft YaHei", sans-serif, "Apple Color Emoji", "Segoe UI Emoji", "Noto Color Emoji"; }
  ```
- **结论**：emoji 在本项目「跨平台 + WebView」的运行环境里不完全可控，字体栈一旦被改动就可能复发。这也是建议把核心视觉从 emoji 迁移出去的根本原因。

### 第一层：棋盘单位图标 —— 内嵌 SVG（必须，无替代方案）

1. 单位图标改为**内联 SVG symbol 精灵图**：
   ```html
   <svg style="display:none"><symbol id="ic-fencer" viewBox="0 0 24 24"><path d="…"/></symbol>…</svg>
   ```
   使用时 `<svg class="unit-icon"><use href="#ic-fencer"/></svg>`。
2. 图标 `fill` 统一用 `currentColor`，以便随状态着色（受伤变红 / 眩晕变灰 / 敌我区分色）。
3. 风格统一为**单色线性图标**（stroke 风格），与现有暗色棋盘（背景 `#1a1a2e`）协调。
4. 顺带修掉两个语义错配：泥岩不再用齿轮、阿米娅不再用派对脸。

**为什么棋盘单位必须是 SVG（不能用 PNG 替代）**：单位要随状态变色 —— 受伤变红、眩晕变灰、敌我不同色。SVG 用 `fill="currentColor"` 一行搞定；PNG 必须准备「正常 / 受伤 / 眩晕 / 敌方」四套图，资源量 ×4 且无法平滑过渡。

- 内嵌**不破坏「单文件 HTML」核心约束**：零外部请求
- 体积可控：7 个单色线性图标，每个 path 约 200–500B，合计 **≈3KB**（当前 261KB，增重约 1%）
- 矢量任意缩放不糊；emoji 是位图字形，放大后边缘发虚

### 第二层：角色立绘 —— 外链 WebP（选角界面等大图）

选角界面的角色展示可使用位图立绘，但**必须外链，不得内嵌**：

- 存放位置：自有服务器，建议路径 `https://<域名>/assets/char/<charId>.webp`
- 格式：**WebP**（比 PNG 小 25–35%，iOS 14+ / 微信 X5 均支持）。AVIF 更小但兼容性有坑，暂不使用
- 尺寸：选角展示建议长边 ≤ 512px；**不要**拿立绘原图去当棋盘图标
- **必须带降级**：`<img src="…webp" onerror="…">` —— 加载失败时自动回退到第一层的内嵌 SVG 图标，保证离线 / 分享 / 网络异常时游戏仍可玩

**体积账（基数 261,228B）**

| 方案 | 增量 | 总体积 |
|---|---|---|
| SVG 图标 7 个（内嵌） | +3KB | 264KB |
| PNG 图标 64px（内嵌 base64） | +20KB | 281KB |
| PNG 立绘 256px ×4（**内嵌**） | +600KB | **861KB（×3.3）** |
| PNG/WebP 立绘（**外链**） | +2KB | 263KB |

> base64 内嵌会额外膨胀 **33%**，这是「内嵌立绘」必须避免的根本原因。

**若手上只有 PNG 素材**

1. **简单图形 / 剪影 / 单色图标** → 用 potrace（免费）或 Illustrator 图像描摹**矢量化成 SVG**，体积降一个数量级并顺带获得变色能力（照片级、复杂立绘无效，别浪费时间）
2. **复杂立绘** → 转 **WebP**（`cwebp` 或在线转换）
3. **多张小图标** → 合并为**雪碧图**，省掉重复的文件头与请求开销

| 方式 | game.html 增量 | 结果 |
|---|---|---|
| **外链服务器（推荐）** | **+3 KB** | **264 KB** |

| base64 内嵌 | +314 KB（再 +33%） | 575 KB |

> 外链是唯一合理选项：内嵌会让单文件从 261 KB 涨到 497–575 KB（×1.9–2.2）。

**优化三步（建议全做）**
1. **svgo 压缩**：SVG 是文本，去元数据 / 合并路径，通常 **-30%~50%** → 236 KB 降到约 120–165 KB
2. **服务器开 gzip / brotli**：SVG 文本压缩率极高，传输量再 **-70%** → 实际约 35–50 KB
3. 优先选体积小的物种（如外星人用月石 9.9 KB 而非代欧奇希斯 37.8 KB）

**技术约束：着色方式要改**

这些是**彩色复杂立绘**（多个 path 各自带 fill），**不是单色图标**：
- ❌ 不能用 `fill="currentColor"` 统一变色 —— 会毁掉原图配色
- ✅ 改用 **CSS filter**，且 **外链 `<img>` 也能生效**（filter 作用于元素本身，不需要访问 SVG 内部）：
  - 眩晕 / 失能 → `filter: grayscale(1) opacity(.7)`
  - 受伤闪红 → `filter: brightness(1.4) sepia(1) saturate(5) hue-rotate(-30deg)`
  - 敌方阵营 → `filter: hue-rotate(180deg)` 或 `drop-shadow(0 0 4px #f66)`

> 因此**第一层方案里「fill: currentColor」这条对本套素材不适用**，改为 CSS filter 实现，验收标准相应调整。
