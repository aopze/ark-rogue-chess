# 风笛「高效冲击」：冲锋攻击次数 = 剩余移动步数

- **提出人 / 时间**：人类维护者 / 2026-10-28 01:20（01-28 01:35 修正口径）
- **类型**：balance（角色核心技能机制改动）
- **优先级**：P1 明显影响体验
- **状态**：ready

> **⚠️ 口径变更（2026-10-28 01:35，以本节为准）**
> 初版写的是「攻击次数 = 冲锋段格数（沿朝向到墙的格数）」。人类维护者改为：
> **「冲锋攻击次数取决于剩下的移动步数」**。
> 本文档已按新口径重写，初版口径作废。**实现时不要再用 `chargePath.length` 的原始到墙长度作为额度。**

## 现状

风笛（`wheelchair`）技力满 5 后，双击路径节点设技能节点 → 到达该步发动「高效冲击」：

1. **冲锋段**：`computeStraightChargePath()`（1378–1395 行）从触发点沿朝向一直延伸到撞墙/出界，得到 `chargePath`。
   **注意：这个函数完全不受移动力限制** —— 即使本回合只剩 1 步移动力，也能冲到墙边 6 格。
2. **冲锋期间**（`playerChargingThisTurn`）：
   - 免疫一切伤害（`IMMUNE_CHARGE`）
   - 撞到敌人 → 造成 `meleeDmg × 2` 的「冲锋撞击」**一次**
   - 敌人**没死就停下**（`playerBlocked = true`），冲锋结束
   - 敌人死了则穿过继续冲
   - 攻击节点被禁用：`attackIndices = attackIndices.filter(idx => idx < chargeIdx)`
   - 全程未造成伤害却撞墙 → 失去一半 HP

**问题**：冲锋段有 N 格，但实际最多只打「一次撞击」；且冲锋距离与玩家本回合剩余的移动力毫无关系（白嫖位移）。撞上第一个没秒掉的敌人就停，N 格的意义只剩位移，与「沿直线高速冲锋撞穿敌阵」的直觉不符。

## 期望

**核心：进入冲锋时，攻击额度 N = 本回合剩余移动步数；冲几格打几次，每次 `meleeDmg × 2`。**

### 1. 额度 N 的计算（最容易写错的一步）

```js
// 错误写法：player.move - chargeIdx
//   chargeIdx 是路径下标，而路径里同时含「移动步」和「等待步」，
//   等待步不消耗移动力，用它减会算少。
const usedMove = countMoveSteps(playerPath.slice(0, chargeIdx + 1));  // 到触发步为止已用的移动步数
const remaining = player.move - usedMove;                             // 剩余移动步数 = N
if (remaining <= 0) { /* 无法发动，见「边界」 */ }
```

- `player.move` 为 `max(1, ⌊敏/2⌋)`，风笛初始 5（敏 10）。
- 等待步通过 `countWaitSteps()` 独立计数，上限也是 `move`，**不计入移动步数**。

### 2. 冲锋距离 = 额度 N

`computeStraightChargePath()` 增加一个 `maxSteps` 参数，沿朝向最多推进 N 格：

- 中途撞墙 / 出界 → 提前停，`stopReason: 'wall'`
- 走满 N 格仍未撞墙 → `stopReason: 'budget'`（新状态，日志区分「步数用完」与「撞墙」）

**这是本次改动对风笛位移的削弱**：原先可冲到墙边 6 格，现在最多冲「剩余移动步数」。
换来的策略维度是**触发放得越早，冲得越远、打得越多**；加敏捷（`dex`）提升移动力可直接拉长冲锋。

### 3. 攻击次数 = 实际冲锋格数

每前进 1 格消耗 1 次额度，对**朝向方向上**的敌人结算（严格按 `isFacingTarget`，不打侧面与背后）。
冲锋格数因撞墙提前结束时，未用掉的额度**作废**（与现有撞墙惩罚一致，不放宽）。

### 4. 被敌人挡住时

仍按现有语义**立即停下**（不再前进），但**剩余额度不作废** ——
改为对**朝向前方 3 格范围内的敌人**继续逐次输出，直到额度用完：

- 目标挑选：优先距离最近的存活敌人（通常就是挡住你的那个）；打死后再顺延到范围内下一个。
- 范围内没有敌人则该次落空，不累积。

### 5. 保持不变

- 冲锋期间免疫一切伤害
- 冲锋段仍整段替换原规划路径；冲锋后的路径节点 / 攻击节点仍被丢弃
- 全程未造成伤害又撞墙 → 失去一半 HP（撞墙判定在「停下后继续攻击」之后结算，若期间打中过敌人则免伤）
- 占一次动作（技能节点）
- 撞墙提前停时，剩余额度作废（与原「撞墙就结束」一致）

### 6. 边界：N = 0 时不能发动

第 1 关开局 `wheelchairSp = 0`，技力按「同方向连续移动 N 步 = +N 点」累积，**攒满 5 点正好要走满 5 步** → 触发点必然在最后一步 → 剩余移动步数 = 0，无法发动。

- 处理：`prepareWheelchairCharge()` 返回 `null`，**技力不清零**（沿用现有「未发动就保留」逻辑），
  日志改为 `「高效冲击」无法发动：本回合剩余移动步数为 0，请下回合把技能节点放在前几步。`
- 这是**预期行为**，不是 bug。实装后第 1 关玩家需要"攒满 → 等一回合 → 下回合第 1 步发动"。
- 若认为这一回合等待体验太差，可选放宽：`remaining <= 0` 时按 N=1 保底（**需人类维护者单独拍板，默认不做**）。

### 7. 文案同步

- 风笛 `tips` 里 `[高效冲击]` 那条：改为「冲锋距离 = 剩余移动步数，冲几格打几次」
- `prepareWheelchairCharge()` 的日志：显示 `本次冲锋 ${N} 步（剩余移动步数），预计 ${N} 次攻击`
- 仪表盘「步数」格已在显示 `已用/总`，可顺带在冲锋就绪时标注剩余可用冲锋格数

## 验收标准

- [ ] 风笛敏 10（move=5），技能节点放在第 1 步 → 日志显示「剩余移动步数 5」，冲锋 5 格、最多 5 次攻击
- [ ] 同一局面把技能节点放在第 3 步 → 剩余移动步数 3，冲锋 3 格、最多 3 次攻击
- [ ] 路径中插入 1 个等待步后再触发 → 剩余步数**不受等待步影响**（仍按移动步数计）
- [ ] 冲锋段前方 2 格是墙、剩余步数 5 → 只冲 2 格、2 次攻击，`stopReason = 'wall'`，剩余 3 次作废
- [ ] 第 1 关攒满技力在最后一步设技能节点 → 提示「剩余移动步数为 0，请下回合」，**技力不清零**，无报错
- [ ] 冲锋段第 2 格有敌人（HP 够抗 1 下不死）→ 第 2 格打 1 次后停下，剩余额度继续打该敌人（或朝向 3 格内其他敌人），总次数 = N
- [ ] 侧后方（不符合 `isFacingTarget`）的敌人**不吃**任何一次冲锋伤害
- [ ] 冲锋期间玩家不吃任何伤害（外星人狙击 / 近战 / 相杀均免疫）
- [ ] 全程未造成伤害且撞墙 → 掉一半 HP；期间造成过伤害 → 撞墙免伤
- [ ] 日志能看出「本次额度 N 次（剩余移动步数）、已命中 M 次」
- [ ] 横屏（桌面）与竖屏（390×844）均正常，无新增 JS 报错
- [ ] 风笛 `tips` 文案与新机制一致

## 备注

- **平衡影响（相对初版口径的变化）**：
  - 初版「冲锋段格数」= 到墙的距离，实测常有 5~6 格 → 10~12 倍近战输出，属于大幅增强。
  - 现口径「剩余移动步数」通常为 **2~4**（要预留步数走到触发点）→ 4~8 倍输出，且**冲锋位移同时被削弱**（不再白嫖到墙）。
  - 综合看这次口径修正是**收敛性改动**，风险低于初版。
- 若实测仍过强，备选收敛方案（需人类维护者拍板）：
  ① 只对「撞击首个敌人」保留 ×2，后续补充攻击降为 ×1；
  ② 攻击额度上限封顶（如最多 4 次）；
  ③ 停下后补充攻击的射程由 3 格收紧为 1 格。
- 「朝向 3 格」按**朝向直线方向 3 格**理解（`facing × k, k=1..3`）。
  若希望改成「`isFacingTarget` 为真且 `dist ≤ 3` 的所有敌人群体命中」，请说明，实现口径不同。
