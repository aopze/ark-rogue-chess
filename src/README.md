## 搬运原则（`P0.1-4`）

1. **纯移动，不改逻辑** —— 先让结构对，再谈重构。
2. 每批 ≤ 3 个模块，每批跑一遍 e2e。
3. 不要在本目录直接写代码然后期望它生效：**产物是 `game.html`，必须经构建**。
4. **顺序即语义**：`let/const` 提升与初始化顺序都依赖它，新增模块必须插在正确位置并跑全量 e2e。
   - **同槽内**：顺序 = `build/manifest.json` 里 `modules` 的顺序。
   - **跨槽**：顺序 = 模板中 `<!-- @inject:scripts:<id> -->` 的先后，**由模板决定，与清单无关**。
5. **一个模块可以有多段**（`/* @slot:<id> */` 分段，见下）—— 当要搬的代码在模板里**不连续**时用它。
   把两段拼进一个文件再整体注入**会改变求值顺序**（第二段可能落到模板 `const` 声明之前 → TDZ），所以必须用槽位让它回到原位。

### 多段模块怎么写

```js
/* @slot:beforeLayoutV */
/* 来源说明（1 行） */
…第 1 段代码…
/* @slot:beforeLayoutToggle */
/* 来源说明（1 行） */
…第 2 段代码…
```

模板对应位置各留一行 `<!-- @inject:scripts:beforeLayoutV -->` / `…:beforeLayoutToggle -->`。
构建时每段落到同名槽位，**等于把代码放回它原来的位置**，因此归一化比对仍可完全一致。
槽位名缺失或模板留了没有模块的标记，构建都会**抛错**（不静默）。
另外产物里若残留 `@inject` 标记，`build/verify.mjs` 会打红 —— 因为 `<!--` 在 JS 里等同注释，标记没被替换**不会报错**，只会静默少一段代码。

## 与根目录 `net/` 的区别

根目录 `net/` 是**已上线的联机模块及其测试脚本**（`net.js`、`room-server.py`、`*_test.mjs`）。
这里的 `src/net/` 是拆分后的**源码归属目录**。拆分完成前两者并存，不要混淆。

详见 `docs/ARCHITECTURE.md`。
>
> **新增/搬移模块后，`build/bundle.mjs` 的「无重复定义」校验必须为绿** ——
> 它会把「模板里还留着已拆代码」这类事故（函数定义两遍、静默覆盖）当场打红。
